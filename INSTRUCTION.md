# Запуск автотестов и результаты

## Окружение проверки

- ОС: Windows 11, 64-bit, версия 26H2.
- Браузер: Chromium 156.0.8078.4.
- Playwright: 1.64.1.
- Pytest: 8.3.5.
- Python при локальном запуске: 3.13.15.
- Тестируемая страница по умолчанию: https://rcsi-science.github.io/demo-roomly/.

## Чек-лист
Подготовленный чек-лист находится в файле Checklist.txt в корне проекта.

## Запуск в Docker

Требуются Docker Desktop и Docker Compose v2. Отдельно устанавливать Python, Playwright или браузер не нужно.

1. Запустить Docker Desktop.
2. Открыть терминал в корне репозитория.
3. Выполнить:

```bash
docker compose run --build --rm tests
```

Команда соберет тестовый образ, установит зависимости и запустит все тесты в Chromium.

## Локальный запуск

При локальном запуске требуется Python. Рекомендуется использовать виртуальное окружение `.venv`.

Активация в Git Bash:

```bash
source .venv/Scripts/activate
```

Активация в PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей и запуск:

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium
python -m pytest
```

Для запуска отдельного теста:

```bash
python -m pytest tests/test_booking.py::test_successful_booking
```

## Результаты

После запуска результаты сохраняются в каталоге `artifacts/`:

- `artifacts/junit.xml` — JUnit-отчет;
- `artifacts/browser/` — скриншоты и trace при падении тестов.

## Вопросы и допущения по требованиям, проверенные области, риски и ограничения проверки

### Вопросы по требованиям

- Какие браузеры, их версии и мобильные устройства должны поддерживаться?
- Существуют ли часы работы переговорных и ограничения на бронирование в ночное время?
- Что считается рабочей почтой: любой адрес корректного формата или только адрес в домене компании?
- Должны ли применяться ограничения к длине имени и допустимым символам?
- Должна ли система проверять пересечение с существующими бронированиями при появлении серверной части?

### Допущения

- Минимальная длительность 30 минут и максимальная длительность 4 часа считаются допустимыми граничными значениями.
- Дата и время интерпретируются в локальном часовом поясе пользователя.
- Под рабочей почтой понимается адрес, соответствующий общему формату email; принадлежность к домену компании не проверяется.
- Количество участников должно быть целым числом от 1 до 20 и не превышать вместимость комнаты.
- Проверка реальной занятости комнат и пересечения бронирований не входит в текущий объем, поскольку приложение не хранит и не отправляет данные.

### Проверенные области

Следующие сценарии подтверждены автотестами в Chromium:

- Доступность опубликованной страницы и отображение кнопки «Забронировать».
- Успешное бронирование с корректными данными.
- Наличие в сообщении об успехе правильных комнаты, даты, времени и имени заявителя.
- Отклонение бронирования малой комнаты при пяти участниках вместо допустимых четырех.
- Воспроизведение дефекта BUG-01: бронирование длительностью пять часов принимается без сообщения об ошибке.

При ручном тестировании были выявлены дефекты, описанные в файле Bugs.docx.

### Риски

- В браузерах, отличных от Chromium, могут остаться ошибки JavaScript-валидации, элементов даты и времени или верстки.
- Проверки, связанные с текущим временем, сменой даты и часовым поясом, не покрыты автотестами и могут содержать незамеченные дефекты.
- Непроверенные граничные значения длительности и количества участников могут обрабатываться некорректно.
- Проблемы мобильной верстки, работы с клавиатурой и доступности сообщений не обнаруживаются текущими автотестами.

### Ограничения проверки

- Автоматизированные проверки выполнялись только в Chromium, как предусмотрено конфигурацией проекта.
- Реальные мобильные устройства, Safari и другие браузеры в рамках автоматизации не проверялись.
- Из-за отсутствия серверной части невозможно проверить сохранение бронирований, одновременную работу пользователей и серверную валидацию.
- Текущие автотесты не заменяют полный ручной проход по чек-листу.
